## Findings and changes

- At 1280×720, Tuning's component column was 1222 px tall inside a 511 px grid
  row. Older menu CSS set `overflow: visible` and let implicit rows stretch the
  preview and characteristics below Save. Explicit row ownership, bounded
  panels and an independently scrolling control column repair this. At wider
  sizes Rates/PID and Level/Throttle form paired groups. Smaller screens use a
  scrolling page with content-sized rows instead of overlapping panels.
- Hangar's single vertical scale stack forced important values behind a
  scrollbar. A two-column scale area, compact spacing and a wider information
  panel show the primary values in 720p. Removed the duplicate selected status;
  the existing disabled Selected for flight action already states it. Roster
  cards retain space for thumbnails and up to two name lines; labels do not
  collapse or crop vertically.
- Tuning no longer inherits nested panel borders. Numeric field sizing no
  longer inflates the Launch control toggle. The graph uses its available width
  and its legend matches the actual roll/pitch/yaw curve colors.
- Graphics puts Display and Scene quality side by side on desktop, with effects
  beneath. Presets fit a consistent row, switches align with their row labels,
  and long implementation-oriented labels are shortened. IDs, stored values,
  numeric bounds and event bindings remain the same.
- Added missing RU/UZ translations for Workbench count/status, native component
  explanations and fullscreen state. Dynamic status writes use the existing
  localization helper. Names, units and technical controller terms are retained.
- A previous-value marker is shown only for a characteristic whose displayed
  value actually changes. No universal green/red improvement rule is introduced.
