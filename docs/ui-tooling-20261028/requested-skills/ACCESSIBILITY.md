# Accessibility Review: ангар PARVOZ

**Ориентир:** WCAG 2.1 AA. **Дата:** 28 октября 2026, Asia/Tashkent.
**Статус:** ограниченная проверка изображения, исходников и заданной палитры.
Полная приёмка WCAG не выполнена.

Применён официальный
[`accessibility-review`](https://github.com/anthropics/knowledge-work-plugins/blob/2574e29377c7173d0cecffef29a6ecbd7f8ccb5d/design/skills/accessibility-review/SKILL.md).
В его краткой таблице 44×44 ошибочно помещены среди AA-проверок. В
[оригинальном WCAG 2.1 критерий 2.5.5 имеет уровень AAA](https://www.w3.org/WAI/WCAG21/Understanding/target-size.html).
Здесь 44×44 используются как желательная цель, а не как самостоятельное
основание объявить нарушение AA.

## Summary

Подтверждён один пробел клавиатурного управления в проверенном локальном
модуле: вращение осмотровой камеры связано с pointer drag без клавиатурного
эквивалента в этом контроллере. Это результат чтения исходников, не прохождения
реального сценария. Три группы визуальных/семантических рисков требуют
браузерной проверки. В макете рассчитаны девять сочетаний контраста, все выше
использованных порогов. Соответствие всей игры не установлено.

## Color Contrast Check — только заданные цвета макета

Расчёт по относительной яркости sRGB, без округления до сравнения с порогом.
Порог текста следует [WCAG 1.4.3](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html).
Панели макета непрозрачные. Эти значения не измерены в текущем публичном DOM;
цвета антиалиасинга текста на скриншоте не выдаются за исходные CSS-цвета.

## Screen Reader / остальные проверки

NVDA/VoiceOver не запускались; автоматического axe-скана и проверки 200% zoom
не было. Пустой `alt` у миниатюры внутри кнопки сам по себе не ошибка:
название уже находится в её тексте. Нужно проверить фактическое доступное имя,
объявление выбора, фильтра и загрузки/ошибки модели.

Причина ограничения live-проверки: Browser вернул
`Local browser use is disabled in Work settings`. Его настройки не обходились.
Публичные кэши и пользовательские сессии в этом ходе не менялись.

## Priority Fixes / будущая приёмка

1. Предусмотреть клавиатурный доступ к осмотру камеры в плане реализации.
2. Проверить и сохранить видимые имена/фокус/семантику каталога после обновления.
3. При доступном Browser выполнить keyboard-only, NVDA, 200% zoom, контраст
   всех состояний и реальные CSS hit areas на согласованной реализации.
   Статичный PNG эти пункты закрыть не может.
