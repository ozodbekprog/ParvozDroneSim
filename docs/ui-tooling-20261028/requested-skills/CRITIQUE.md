# Design Critique: текущий ангар PARVOZ

28 октября 2026, Asia/Tashkent. Применён официальный
[`design-critique`](https://github.com/anthropics/knowledge-work-plugins/blob/2574e29377c7173d0cecffef29a6ecbd7f8ccb5d/design/skills/design-critique/SKILL.md).
Это применение методики агентом к изображению и коду, а не отзыв сервиса Canva
или независимого дизайнера.

## Overall Impression

Настоящий дрон на рабочем столе сразу сообщает назначение ангара. Это сильная
часть существующего экрана, которую пользователь предпочёл предыдущим
вариантам. Основная возможность улучшения — читаемость периферийного UI,
особенно распознавание дронов и плотность полезной информации справа.

Источник визуального анализа — [прямой снимок публичного UI](../../ui-research-20261028/realistic/evidence/public-hangar-ui.png)
от 28 октября, `index-OPei9JC_.js`. Текущий локальный checkout уже содержит
отдельные исправления имён/шкал. Его код не считается доказательством того,
что эти исправления опубликованы. Свежая браузерная проверка заблокирована
настройкой Work; повторный вход, очистка кэша и новый публичный захват не выполнены.

## Usability

| Finding | Severity | Recommendation |
| --- | --- | --- |
| Внизу видны миниатюры и классы, но отсутствуют строки с именами. Игроку сложно отличить сборку от базовой модели | Critical для задачи выбора | Постоянная строка имени под изображением; место для длинного имени не должно зависеть от высоты картинки |
| У выбранной Luma 5 Copy 1 на публичном снимке пустая миниатюра | Moderate | Обеспечить отдельный preview копии; до его готовности обозначать fallback, не оставлять пустую карточку |
| Шесть карточек занимают около 60% ширины большого нижнего блока | Moderate | При небольшом списке распределить их по доступной ширине. При большой коллекции сохранить горизонтальный каталог и навигацию; шесть карточек не являются постоянным продуктовым пределом |
| В правой панели между данными и действиями большой разрыв, но сами подписи мелкие | Moderate | Увеличить кегль данных и уплотнить логическую структуру панели, заполнить её уже запрошенными физическими характеристиками |
| Статус «выбран» одновременно выглядит как основная отключённая кнопка | Minor | В выбранном состоянии показывать явный статус. Для другой модели оставить действие выбора; сценарий возврата к выбору карты сохранить |

## Visual Hierarchy

- **Первый взгляд:** крупный дрон, затем правая панель. Правильный приоритет
  для осмотра модели. Силуэт нельзя закрывать большими левыми панелями.
- **Порядок чтения:** имя → класс/происхождение → характеристики → действия;
  изображения в каталоге → имена → короткие роли. Разброс меток по всему экрану
  и рекламный логотип этому сценарию не помогают.
- **Акцент:** использовать существующий янтарный для выбора и следующего
  доступного действия. Физические шкалы нейтральные: увеличение массы или
  задержки не объявляется улучшением. Пользователь отклонил прежнюю универсальную
  зелёную/красную трактовку.
- **Пространство:** оставить центр открытым, уменьшить пустую площадь справа,
  сделать нижний каталог ровным. Это refinement действующего направления,
  а не новый согласованный стиль.

## Consistency

| Element | Issue | Recommendation |
| --- | --- | --- |
| Типографика | Большой доступный экран, но подписи и карточки воспринимаются мелкими | Сохранить Source Sans 3; упорядочить размеры названий, значений, подписей |
| Карточки | Выбранное состояние видно по контуру, но выбранный preview пуст | Добавить текстовое состояние и реальную миниатюру, не полагаться только на цвет |
| Статистические блоки | У массы и времени разные длины подписей, значения разнесены | Значения выровнять; единицы писать рядом; шкалы трактовать одинаково во всех экранах |
| Навигация | В ангарах и предыдущих концептах менялись местоположения функций | В этой пробе сохранить каталог снизу и инспектор справа; zoom/reset остаются видимыми |

## Accessibility

Расчётные значения для макета и ограничения проверки вынесены в
[ACCESSIBILITY.md](ACCESSIBILITY.md). По PNG невозможно проверить Tab,
Enter/Space, объявление состояния экранным диктором или масштабирование браузера.
Они не считаются пройденными.

## What Works Well

- Реальная сцена и изображения моделей дают игровому UI узнаваемость.
- Каталог снизу поддерживает прямой выбор и не перекрывает основную модель.
- Сдержанная существующая палитра позволяет улучшить читаемость без ребрендинга.
- В локальном коде уже есть настоящие buttons, `aria-pressed`, сохранение фокуса
  каталога и подписанные кнопки камеры. Эти решения следует сохранить.

## Priority Recommendations

1. **Вернуть распознавание коллекции:** имя плюс изображение в каждой карточке,
   явное выбранное состояние и корректный preview копии.
2. **Перераспределить плотность:** использовать свободную ширину каталога,
   дать характеристикам читаемый размер, убрать длинный пустой участок панели.
3. **Проверить состояния до переноса:** другой выбранный дрон, длинное имя,
   заблокированный оригинал, много копий, загрузка/ошибка preview и узкий экран.
   Картинка с шестью доступными моделями не покрывает эти сценарии.

Результат рекомендаций показан в [статичном макете](hangar-refinement.png).
Следующий этап после визуального выбора — согласование плана; изменений
игровой реализации в этом пакете нет.
