# Aircraft electrical details and optional action camera

Started 15 October 2026; source/artifact verification completed 16 October.
This note records the additive art. Runtime integration, actual browser checks,
GitHub and any publication are owned by the main task and recorded separately.

The missing Luma battery leads were procedural source Bezier paths, rather than
MeshRenderer meshes. The previous importer exported meshes and skipped these
paths. It also explicitly skipped the optional action camera. The preserved
cache contained the original control points, connection polarity, camera meshes,
UVs, materials and mounting information; no new game extraction was necessary.

The four imported aircraft now have their active authored frame leads restored.
Each compatible battery has a separate pair of leads whose last segment joins
the corresponding frame terminal. Source exits and initial tangents remain
unchanged. Inactive alternative frame paths are excluded. The eleven battery
arrangements cover three batteries each on Luma, Chameleon and Dquad, and two on
Gecko. Kestrel retains the detailed electrical geometry already in its licensed
authored model; its addition is the optional camera.

All five aircraft receive a removable action camera. Luma uses the preserved
Front HD assembly with its authored four-bolt mounting base. This prefab is
already frame-relative: applying the action camera slot again would make it
float. Chameleon and Dquad use the preserved Session assembly and native slots.
Gecko and Kestrel use the same camera, base and strap with adapted top-plate
placement. Kestrel's mounting height was checked against its actual source-frame
surface. The camera remains cosmetic for this phase; its displayed 74 g / 133 g
source mass is informational and does not change flight physics.

## Saved art and contract

- `content/shared-assets/drone-details/details.blend` contains editable source
  camera meshes, packed textures and editable Bezier leads for every arrangement.
- The `hangar`, `low` and `far` source/delivery GLBs are independent additive
  assets. Original complete aircraft deliveries and editable sources remain
  intact. No map export occurred.
- `SOURCE.json` preserves the Liftoff origin, credited authors, unconfirmed
  redistribution permission and the existing limited online-test scope.
- `preparation.json` records source path IDs, terminal positions, compatible
  battery arrangements and camera placement. `validation.json` inspects the
  actual compressed deliveries.
- Each `content/drones/<id>/details.json` is the integration sidecar.
  `visualDetails` selects `frameNode` and the battery ID's `batteryNodes` entry.
  `accessories.actionCamera` selects the camera node in the same shared asset.
  All detail nodes use the existing aircraft's source coordinate system and
  receive the same `modelTransform` as its complete model. The build flag is
  `actionCamera`, default false.

The shared Low file is approximately 2.2 MB. It contains every arrangement, but
only the selected aircraft, selected battery and optional camera are displayed.
All twelve textures are KTX2, at most 512×512, with mip levels; geometry uses
meshopt compression. Solid silicone leads have an authored UV unwrap. Unused
UVs can be pruned from their untextured delivery material.

## Verification and continuation

`node tools/check-drone-details.js` passes all three compressed LODs, all eleven
battery arrangements, all eight active source frame leads, named-node retention,
source UVs, KTX2 dimensions and source provenance. Source joins are exact. The
nearest compressed terminal-cap vertex remains within the 1.2 mm cable radius.

Blender Low reviews use the actual reduced detail geometry and retained reduced
aircraft geometry, from front, rear and side. The inspection caught and corrected
the initial Luma double-applied socket and the Kestrel mounting height. The
studio lighting differs from the game's Low environment. Browser acceptance is
a separate integration check. Review images are generated by
`tools/blender/review_drone_details.py`; raw captures remain in ignored
`data/drone-detail-20261015/review/`.

For ordinary art edits, open `details.blend`, preserve the semantic node names,
then run these minimal commands (the first command needs the configured Blender
executable):

```powershell
& 'D:/Programs/Blender Foundation/Blender 5.1/blender.exe' --background --python tools/blender/export_saved_drone_details.py
node tools/prepare-drone-details.js
```

The saved-source export works without the game installation or ignored recovery
cache. Packaging reuses unchanged compressed textures where a local fingerprint
cache is present. The independent validation runs at the end.

`restore_drone_details.py` is the explicit reconstruction route from the preserved
recovery cache, and overwrites the detail source/sidecars. Do not use it to export
manual Blender edits. It retains the first previous `.blend` in ignored
`data/drone-detail-20261015/before/`. No original aircraft source, texture atlas,
logo, credit or permission record was removed or disguised.

The art workflow itself does not publish. Integration was published and finalized

verified the Luma cosmetic-camera save/use and selected home model; local Low
also checked battery swapping. Exact release/backup checks are recorded in
