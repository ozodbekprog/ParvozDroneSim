# Моделирование в открытом Blender через MCP

Работа выполняется в открытом Blender 5.1 через Blender MCP: Python-код с `bpy`
создаёт обычные редактируемые сетки, материалы и коллизии в текущей сцене.
Подключение описано в [BLENDER-MCP.md](BLENDER-MCP.md), общий экспорт —
в [BLENDER-WORKFLOW.md](BLENDER-WORKFLOW.md).

Проход рассчитан на 12 официальных карт: `harborworks`, `hangar`, `forest`,
`pinecrest`, `ridgeway`, `industrial`, `nightgrid`, `neon`, `orbital`, `canyon`,
`ruins`, `sunscar`. Он добавляет ориентиры средней детализации и проёмы для
близкого полёта; исходная геометрия сохраняется, кроме отдельных заменяемых
участков. ID карт и существующие трассы сохраняются.

**1 октября 2026 года все 12 карт опубликованы из открытых сцен Blender.**
В `data/live-blender-modeling.json` есть 12 записей с результатами экспорта.
Для Canyon и Sunscar в этом проходе также созданы слоистые формы скал.

## Исходники и результат

```text
content/maps/<map-id>/
  map.blend                  редактируемый исходник
  model.glb                  модель для игры
  map.json                   настройки карты
  collision.json             отдельные физические коллизии
  thumbnail.png              рендер из камеры Blender
  textures/blender-painted/  изображения цвета и нормалей
  authoring.json              сведения об авторской сцене и live-публикации
content/races/<course-id>/race.json
data/live-blender-modeling.json
```

Откройте `content/maps/<map-id>/map.blend` через **File → Open**. Добавленная
геометрия находится в коллекциях с префиксом **MCP Authored**; мастерская
Harborworks — в **09 Harborworks crafted pilot workshop**. Объекты, сетки,
модификаторы и материалы можно править отдельно. Коллизии находятся в
**COLLISION_PROXIES** или коллекциях **MCP Authored … collision proxies**.
После публикации помощники скрыты в viewport; включайте нужные объекты через
Outliner для редактирования ворот и коллизий.

## Порядок работы через MCP

1. Откройте канонический `map.blend`, проверьте ID текущей сцены и сделайте
   резервную копию перед моделированием.
2. Выполняйте этапы отдельными вызовами MCP `execute_blender_code`, проверяя сцену между
   этапами. Функции моделирования сами не сохраняют и не экспортируют карту.

| Скрипт в `tools/blender/` | Вызовы внутри открытого Blender |
|---|---|
| `live_harborworks.py` | `phase1()`, `phase2()`, `phase3()` — мастерская Harborworks |
| `live_map_models.py` | `setup(map_id)`, `architecture(map_id)`, `details(map_id)`, `finish(map_id)` — остальные 11 тем |
| `live_surface_materials.py` | `apply()` — PBR-изображения и UV для подходящих поверхностей |
| `live_check.py` | `check()` — новые коллизии около стартов и центров ворот |
| `live_publish.py` | `preview()`, затем `publish()` — миниатюра, сохранение и экспорт текущей сцены |

Например, для уже открытой карты Hangar:

```python
import sys
sys.path.insert(0, r'C:\DroneLiftoffUz\tools\blender')
import live_map_models as live
print(live.setup('hangar'))
# Следующие этапы выполните отдельными вызовами MCP:
# print(live.architecture('hangar'))
# print(live.details('hangar'))
# print(live.finish('hangar'))
```

`setup()` заново создаёт собственную добавленную коллекцию: повторный запуск
заменит ручные правки в ней. Для обычного редактирования готовой карты меняйте
объекты непосредственно в Blender. Этапы Harborworks загружайте через
`runpy.run_path(...)`, как показано в [HARBORWORKS-LIVE-MODELING.md](HARBORWORKS-LIVE-MODELING.md).

3. Выполните `live_surface_materials.apply()`, проверьте материалы и вид из
   камеры. Цветовые и normal PNG сохраняются в `textures/blender-painted/`,
   пакуются в `.blend` и встраиваются в экспортируемый GLB.
4. Выполните `live_check.check()` и исправьте найденные `hardConflicts`.
   Проверка охватывает только новые прокси у стартов и центров ворот; она не
   подтверждает проходимость всех проёмов и не заменяет полёт в игре.
5. Выполните `live_publish.preview()`, осмотрите `thumbnail.png`, затем
   `live_publish.publish()`. Публикация требует канонический путь
   `content/maps/<id>/map.blend`, делает резервную копию в
   `data/blender-backups/`, сохраняет сцену и экспортирует её текущие данные.

`publish()` записывает результат каждой карты в
`data/live-blender-modeling.json`: число объектов, коллизий, трасс, размер GLB и
путь резервной копии. Проверяйте этот журнал для результатов последней
публикации каждой карты.

## Синхронизация и последующие правки

После live-публикации выполните в терминале проекта:

```powershell
npm run content:sync
npm run content:check
npm run build
```

После последующих ручных правок сохраните `.blend` и используйте существующий
экспортёр:

```powershell
npm run content:blender -- --map harborworks --publish
```

Эта команда запускает отдельный Blender и читает сохранённый файл. Она также
выполняет синхронизацию и проверку контента; сборка остаётся отдельной командой.
В игре проверьте изменённые проходы и столкновения. Рендеры и геометрические
проверки не подтверждают длительное тестирование всех трасс.

## Проверка опубликованного прохода — 1 октября 2026

Все 12 GLB проверены на целостность буферов, геометрии и встроенных изображений;
403 экспортированных mesh-примитива имеют UV. Авторские помощники, прокси
коллизий, ворота и старты в визуальные GLB не попали. ID карт, 19 трасс,
146 ворот и 19 стартов совпадают с резервной копией без численных изменений.

Проверка [course-layout-live-blender.json](../data/course-layout-live-blender.json)
не обнаружила конфликтов стартов, центров ворот, направления, опор и границ.
25 предупреждений о прямых отрезках между воротами совпадают с предыдущим
аудитом; они требуют оценки маршрутов в полёте и не являются результатом
добавленного моделирования. `content:sync`, `content:check` и короткая сборка
Vite прошли. Длительные полёты и испытания производительности не выполнялись.
