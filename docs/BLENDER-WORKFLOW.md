# Карты, коллизии и трассы в Blender

Blender установлен здесь: `D:/Programs/Blender Foundation/Blender 5.1/blender.exe`.
Команда `content:blender` использует этот путь автоматически. На другом компьютере
передайте `--blender "путь/blender.exe"` или задайте переменную `BLENDER_PATH`.
Это инструмент разработчика: его нет в меню игроков.

## Единые исходники

Все официальные карты используют тот же формат пакетов, что и ваши дополнения:

```text
content/maps/<map-id>/
  map.blend       редактируемая сцена Blender
  map.json        ID, название, атмосфера и настройки карты
  model.glb       модель для браузера, экспортируется из Blender
  collision.json  физические коллизии, экспортируются из Blender
  thumbnail.png   небольшое настоящее изображение карты
  textures/       изображения материалов авторской сцены
content/races/<course-id>/race.json
content/challenges/<mission-id>/challenge.json
content/tutorials/<lesson-id>/tutorial.json
content/drones/<drone-id>/drone.json + model.glb
content/parts/<part-id>/part.json + model.glb
```

Карта может иметь несколько трасс. Поле `map` в каждом `race.json` связывает трассу
с картой. Задания и уроки ссылаются на те же ID; их правила, тексты и подсказки
редактируются в JSON. Физика и параметры деталей также остаются в JSON.
`public/content/` — автоматически созданные файлы доставки, править их вручную не нужно.

## Работа в открытом Blender через MCP

Blender MCP управляет текущей открытой сценой Blender 5.1. Добавленные ориентиры
и проходы редактируются в коллекциях **MCP Authored …**, а мастерская Harborworks —
в **09 Harborworks crafted pilot workshop**. Это проход средней детализации:
он дополняет исходную геометрию и заменяет отдельные участки.

Этапы моделирования, PBR-текстуры, проверка новых коллизий и экспорт текущей
сцены описаны в [LIVE-BLENDER-MODELING.md](LIVE-BLENDER-MODELING.md).
`live_publish.preview()` создаёт миниатюру, `live_publish.publish()` сохраняет
канонический `.blend` и экспортирует открытую сцену. После этого выполните
`npm run content:sync`, `npm run content:check` и `npm run build`.
Текущий прогресс публикации записывается в `data/live-blender-modeling.json`.
Обычная команда `content:blender` ниже читает сохранённый файл, поэтому перед её
запуском сохраните изменения в Blender.

## Изменить существующую карту

1. Откройте `content/maps/harborworks/map.blend` в Blender. Аналогичный файл есть
   в каждой папке официальной карты.
2. Редактируйте объекты и материалы. Импортируйте новые модели через **File →
   Import → glTF / FBX / Wavefront OBJ**, поставьте их на место старых объектов.
3. В **Outliner** включите нужную коллекцию трассы внутри **90 Flight Authoring**.
   Другие трассы можно скрыть. Красные wireframe-объекты в **COLLISION_PROXIES**
   показывают физические границы.
4. Сохраните `.blend`, затем в терминале проекта выполните:

```powershell
npm run content:blender -- --map harborworks --publish
```

Команда экспортирует геометрию в `model.glb`, коллизии в `collision.json`, положения
ворот и старта — в соответствующие `race.json`. Затем выполняет `content:sync` и
`content:check`. Исходный `.blend` остаётся разбит на редактируемые объекты; только
доставляемый GLB объединяется по материалам с сохранением UV и нормалей. Одинаковые
обычные PBR-материалы объединяются для уменьшения числа вызовов отрисовки.
Камеры Blender, лампы, wireframe-коллизии
и маршрутные метки не попадают в модель игры.

Перед перезаписью создаётся копия в `data/blender-backups/`; путь печатается в
терминале. Если проверка сообщила об ошибке, исправьте её и экспортируйте снова.
Не запускайте массовый генератор карт для обычного редактирования: он предназначен
для воспроизведения первоначального оформления и заменяет ручные изменения.

Если меняли копию `.blend` в другом месте:

```powershell
npm run content:blender -- --map harborworks --source "D:/MyMaps/harborworks.blend" --publish
```

Сама внешняя копия не перезаписывается. Для дальнейшего редактирования сохраните
актуальную авторскую сцену обратно как `content/maps/harborworks/map.blend`.

## Ворота и старт

В коллекции каждой трассы:

- `GATE_<course-id>_001` — центр первого проёма. Перемещайте его вместе с дочерним
  wireframe-контуром. Вращайте вокруг **Z Blender**: игра использует горизонтальный
  поворот ворот. Наклонённые ворота экспортёр пока отклоняет.
- `SPAWN_<course-id>` — положение старта; стрелка показывает направление полёта.
- В **Object Properties → Custom Properties** ворот: `track` — ID трассы;
  `order` — порядок, начиная с нуля; `width`/`height` — чистый проём в метрах.
  Масштабирование ворот по локальным X/Z дополнительно меняет ширину/высоту при
  публикации. Оставляйте положительный масштаб.
- `gateClass`: `precision-5`, `sport-7` или `open`. Название класса обозначает
  сложность, а не запрет на другую модель дрона. В трассах используются проёмы
  примерно **1,8 × 1,6 м**, **3 × 2,4 м** и **6–9 × 4,2–6 м** соответственно.
- `frameThickness` — толщина стойки, 0,05–0,25 м.
- `supportType`: `ground` — ножки до земли; `roof` — до крыши/платформы;
  `suspended` — подвес сверху; `none` — без опор. `supportBaseY` — высота точки
  крепления в метрах, совпадающая с высотой **Z Blender**. После переноса ворот на
  другую платформу исправьте и эту высоту.

Экспорт сохраняет ID трассы, число кругов и порядок существующих ворот. Чтобы
добавить или удалить контрольные точки, сначала измените массив `gates` в
`race.json`, затем обновите метки из JSON. Так старые трассы не меняются случайно
при удалении объекта в Blender.

```powershell
npm run content:blender -- --map harborworks --markers
```

**Эта команда заменяет маршрутные метки в `.blend` данными JSON.** Сначала
опубликуйте положения, изменённые в Blender, если хотите их сохранить. Геометрию
карты она не перестраивает, а существующие физические прокси сохраняет.
После правки свойств размера/опоры публикация + обновление меток также обновит
wireframe-подсказки в авторской сцене.

Для всех официальных карт сразу:

```powershell
npm run content:blender -- --all --markers
```

## Коллизии

Создавайте отдельные простые коллизии, которые соответствуют форме объекта и
оставляют свободными двери, окна и лётные коридоры. Высокополигональная модель не
должна автоматически становиться столь же сложной физической сеткой.

| Объект Blender | Пользовательские свойства | Экспорт |
|---|---|---|
| Куб/параллелепипед `COLLIDER_…` | `flightCollider=true`, `collisionType="box"` | Положение, размеры и поворот коробки |
| Простая замкнутая сетка `COLLIDER_…` | `flightCollider=true`, `collisionType="mesh"` | Треугольники с учётом положения/масштаба/поворота |

Поместите их в `COLLISION_PROXIES`, включите **Display As → Wire** и отключите
рендер камеры. Прокси могут вращаться по всем осям. Повороты преобразуются в
систему координат игры; коробки с отражением или сдвигом от родительского
неравномерного масштаба экспортируются как сетки для сохранения формы.
Одна сетка коллизии ограничена 100 тысячами треугольников. Для автомобильного
силуэта обычно достаточно нескольких коробок; для здания — отдельных стен,
перекрытий и колонн. Тонкие декоративные детали могут обходиться без коллизий.

Если хотите заменить авторские прокси данными `collision.json`:

```powershell
npm run content:blender -- --map harborworks --markers --refresh-colliders
```

Этот флаг явно заменяет изменённые коллизии в Blender. Без него существующие
прокси сохраняются; недостающая коллекция создаётся из текущего JSON.

## Новая карта и материалы

Для новой карты создайте папку с `model.glb` и `map.json` (можно скопировать
настройки существующей карты и изменить ID). Создайте трассы в отдельных папках
`content/races/`, после этого сохраните сцену как `map.blend` и выполните
`--markers`, чтобы получить редактируемые точки и физические прокси.
Миниатюру экспортируйте отдельным небольшим PNG/JPG с камеры Blender.

В игре поддерживаются PBR-материалы: **Principled BSDF**, base color, normal,
metallic/roughness, emissive и совместимые текстуры glTF. Процедурные узлы Blender
нужно запечь в изображения. GLB встраивает поддерживаемые текстуры; Blender-лампы
не переносятся, потому что свет и атмосфера задаются `map.json`.

FBX/OBJ можно импортировать прямо в авторскую сцену. Для отдельного нового пакета
также работает существующий конвертер:

```powershell
npm run content:import -- --type map --id my-airfield --file "D:/Models/airfield.fbx" --blender "D:/Programs/Blender Foundation/Blender 5.1/blender.exe"
```

Текстуры держите рядом с исходным FBX/OBJ. Конвертер создаёт GLB, но не угадывает
ваш игровой дизайн или точные коллизии: проверьте их и задайте отдельно.
Для дрона используйте `--type drone`, для детали — `--type part --category propellers`
(или `frame`, `motors`, `battery`, `camera`). Физические параметры и точки крепления
детали настраиваются в её JSON.

## Координаты и публикация

- Единицы — метры. Blender **Z вверх**; игра/glTF **Y вверх**.
- Преобразование координат: игра `[x,y,z]` → Blender `[x,-z,y]`.
- `modelTransform` карты нужно запечь в авторскую геометрию и удалить из JSON
  перед `--publish`, чтобы не применить преобразование дважды.
- При работающем `npm start` допустимое обновление контента подхватывается после
  выхода из текущего полёта. Публичный постоянный сервер получает эти изменения
  через новую сборку и публикацию; локальный файл сам на удалённый сервер не копируется.
- Никакого загрузчика пользовательских карт в игровом меню нет.

Короткая проверка после редактирования: откройте выбранную карту, пролетите через
изменённые ворота и проверьте стены/проёмы. Длительные полёты и проверку всех
возможных новых моделей выполняет разработчик.
