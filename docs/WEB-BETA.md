# Веб-бета: условия выпуска

Цель — 100 игроков в комнатах 2–8. Веб-бета размещена на [parvoz-drone-sim.duckdns.org](https://parvoz-drone-sim.duckdns.org/) с HTTPS и допуском 20. Импорт базы и восстановление облачной резервной копии проверены; реальная вместимость 100 и UHD 620 пока не подтверждены. Текущее состояние: [ORACLE-DEPLOYMENT.md](ORACLE-DEPLOYMENT.md). VM и резервные копии: [FREE-HOSTING.md](FREE-HOSTING.md). Платежи, Unity и Photon не входят в первую бету. Параметры полёта и ID Kestrel сохранены; художественная приёмка — отдельное условие.

## Аккаунты

В Profile зарегистрированный игрок создаёт/заменяет секретный код после проверки пароля. Сохраните его при показе: сервер хранит только хеш. Новый код отменяет прежний. Forgot Password принимает ник, код и новый пароль, расходует код один раз и отзывает прежние сессии/сокеты. После восстановления войдите и выпустите следующий код. Попытки ограничены по IP/аккаунту.

POST `/api/account/recovery-code` требует сессию и `{password}`. POST `/api/account/recover` принимает `{username,code,newPassword}`. Миграция добавляет nullable recovery_hash, сохраняет старые ID/прогресс. Карьера и рекорды следуют за аккаунтом; калибровка, графика и вручную сохранённые реплеи остаются локально. Личные одиночные и серверные соревновательные результаты сохраняют прежнее разделение.

Допуск учитывает аутентифицированные multiplayer-соединения, включая очередь/лобби. При заполнении возвращается понятная ошибка; существующие игроки продолжают. Закрытие соединения освобождает место, одновременный второй вход одного пилота отклоняется.

## Нагрузочная приёмка

Испытание проводите на выбранной VM с настоящим контентом, отдельным Compose project и базой. Production остановлен, чтобы измерять весь ресурс VM. Не проводите тест во время публичных заездов. CAPACITY_TEST_MODE принудительно использует /data/capacity-test/liftoff.sqlite; генератор отказывается нагружать обычную базу.

В опубликованном каталоге после успешной сборки и резервной копии:

```bash
docker compose --env-file deploy/production.env -f compose.production.yaml stop
docker compose -p liftoff-capacity --env-file deploy/production.env -f compose.production.yaml -f compose.capacity.yaml up --build --wait -d
```

Отдельное имя проекта создаёт отдельные тома. Caddy выпускает тестовый сертификат отдельно. Дождитесь HTTPS и capacityTest:true в /api/catalog. Базу настоящих аккаунтов копировать для синтетической нагрузки не нужно.

На другом компьютере с Node 24 последовательно запустите:

```bash
npm run load:100 -- --url=https://YOUR_NAME.duckdns.org --clients=100 --seconds=3600 --room-size=8 --maps=hangar,forest --cold-assets --report=capacity-room8.json
npm run load:100 -- --url=https://YOUR_NAME.duckdns.org --clients=100 --seconds=3600 --room-size=2 --maps=hangar,forest --cold-assets --report=capacity-room2.json
```

Первый создаёт 13 комнат, второй — 50. Проверьте наличие обеих карт в каталоге. Каждый пилот отправляет команды 60 Гц, получает подтверждения и движущиеся snapshots; завершённые заезды перезапускаются. cold-assets запускает 100 параллельных загрузок самого большого настоящего GLB, учитываемых в месячном трафике. Это проверяет HTTP-выдачу, а полную загрузку выбранной карты в браузере проверяйте отдельно. Если генератор сам перегружен, серверную вместимость он не подтверждает.

До каждого сценария на VM начните отдельную запись метрик, Ctrl+C после него; для второго замените имя файла на server-room2.jsonl:

```bash
docker compose -p liftoff-capacity --env-file deploy/production.env -f compose.production.yaml -f compose.capacity.yaml logs --follow --no-log-prefix --since=1s game > server-room8.jsonl
```

Перенесите метрики/отчёты на один компьютер:

```bash
node tools/check-capacity.js capacity-room8.json server-room8.jsonl
node tools/check-capacity.js capacity-room2.json server-room2.jsonl
```

Метрики каждые 15 секунд: p95 шага, задержка таймера, комнаты, пилоты, RSS, отправленные байты, ошибки и потерянное время симуляции. Автоматический контроль требует час, 100 активных пилотов, две карты, полные загрузки, p95 <16,7 мс, отсутствие ошибок и нарастающего отставания. capacityVerified остаётся false: автоматический отчёт не заменяет остальные пункты приёмки. При неудаче исправляйте измеренное ограничение, затем повторяйте сценарий.

Вернуть production:

```bash
docker compose -p liftoff-capacity --env-file deploy/production.env -f compose.production.yaml -f compose.capacity.yaml down
docker compose --env-file deploy/production.env -f compose.production.yaml up --wait -d
```

Тестовые тома сохраняются; production-том не удаляется. Проверьте обычный каталог, вход и здоровье сервера.

## Остальная приёмка

- Реальные подключения из Узбекистана/СНГ: игровой ping, управляемость, загрузка выбранной карты при слабой связи.
- Потеря связи, повторный вход, занятый сервер и освобождение места, несовпадение протокола/контента. Перезапуск и восстановление облачной копии сохраняют ID, карьеру, XP, открытия и рекорды.
- Внешний health-монитор, приватный bucket, семь копий, таймер и уведомление о его отказе. Проверить откат на VM.
- UHD 620 Low: F4 во время полёта включает 30 секунд прогрева и 180 секунд записи при настоящем framebuffer 1280×720 и выключенной адаптации; F6 скачивает JSON. Пауза, скрытая вкладка, смена сцены/настроек делают замер недействительным. Записать backend, framebuffer, времена кадров, треугольники и draw calls. Медиана ≤16,7 мс, 1% low ≥50 FPS. Бюджет Low: 150–300 тысяч видимых треугольников, до 250 calls и 256 MiB текстур с mip. Отчёт автоматически не подтверждает GPU и объём текстур: проверить отдельно. Другая машина не подтверждает UHD 620.
- Profile/восстановление проверить в реальном браузере; API-тесты не заменяют визуальную приёмку.

Сначала закрытая бета 10–20 людей, затем проверки 50/100. MAX_MULTIPLAYER_PLAYERS повышать после соответствующей приёмки и обновления выпуска. Косметику/набор поддержки планировать после стабильности и оценки возвращаемости игроков; платежи пока не добавлены.
