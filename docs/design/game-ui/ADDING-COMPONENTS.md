# Добавление компонентов в Workbench

Разработчик может добавлять новые детали через папки `content/`. Workbench получает список из каталога: отдельную карточку в коде интерфейса для каждой новой детали создавать не нужно.

## 1. Создайте пакет детали

Рабочая папка проекта: `C:\DroneLiftoffUz`.

```text
content/
  parts/
    motors-torque-2207/
      part.json
      model.glb             необязательно
      paint.png             необязательно
```

Файл должен называться `part.json`. Имя папки удобно составлять из категории и ID; фактическую категорию определяет поле `category` внутри JSON. В каждой категории ID должен быть уникальным. Используйте ID длиной 2–64 символа: строчные латинские буквы, цифры и дефисы; первый символ — буква или цифра.

### Полный пример без дополнительной 3D-модели

Создайте `content/parts/motors-torque-2207/part.json`:

```json
{
  "id": "torque-2207",
  "name": "Torque 2207",
  "category": "motors",
  "mass": 0.018,
  "thrust": 1.08,
  "response": 1.1,
  "drag": 1,
  "duration": 1,
  "durability": 1,
  "cost": 0,
  "position": [0, 0, 0],
  "rotation": [0, 0, 0],
  "scale": 1,
  "materials": []
}
```

Этого достаточно, чтобы новая деталь появилась в категории Motors и влияла на параметры полёта. `name` — название карточки; `id` сохраняется в сборке дрона. У существующей опубликованной детали сохраняйте ID, чтобы сборки пользователей продолжали ссылаться на неё.

## 2. Опубликуйте каталог

Из корня проекта выполните:

```powershell
npm run content:sync
npm run content:check
```

Первая команда собирает пакеты в `public/content/catalog.json`, копирует модели и текстуры в `public/content/assets/` и меняет ревизию каталога. Вторая проверяет опубликованный контент.

`public/content/catalog.json` и файлы с хешами — результат сборки. Исходники редактируйте в `content/`: следующая синхронизация заново создаёт каталог из этих папок.

### Автоматическое обновление

`npm start` сначала синхронизирует контент и собирает клиент. Когда сервер работает с `NODE_ENV`, отличным от `production`, он также следит за `content/` и собирает изменения после короткой задержки. Меню периодически проверяет новую ревизию каталога. Новые детали становятся доступны после обновления каталога; незавершённая сборка в Workbench сохраняется.

Если изменения ещё не появились, вернитесь в Drone Selection и подождите следующий опрос каталога, либо обновите страницу. При ошибке импорта смотрите вывод сервера: невалидный каталог не применяется к запущенной игре. Активные сетевые полёты сохраняют текущий контент; сервер откладывает смену каталога до их завершения.

При `NODE_ENV=production` автоматического наблюдения за папками нет. Синхронизируйте контент, соберите клиент и перезапустите сервер. Для удалённого сервера публикуйте новый комплект клиента, каталога и файлов моделей; локальная папка обновляет только этот экземпляр игры.

## 3. Найдите деталь в Workbench

1. Откройте **Hangar → Drone Selection**.
2. Выберите оригинальный дрон и создайте его копию для изменения, либо выберите существующий дрон из **Modified**.
3. Откройте **Workbench → Parts → Motors**.
4. Найдите **Torque 2207**, выберите его и нажмите **Save changes**.
5. Вернитесь в Drone Selection и выберите **Use drone**, если хотите летать на этой копии.

Оригинальные дроны сохраняют штатную сборку. Изменения деталей сохраняются в модифицированной копии.

## Модели и материалы

Для собственной геометрии положите GLB с встроенными ресурсами в ту же папку. Имя `model.glb` или `scene.glb` распознаётся автоматически. Также можно указать относительный путь через поле:

```json
"model": "model.glb"
```

`position` задаётся в метрах, `rotation` — в радианах, `scale` — множитель масштаба. Модель использует систему координат Y вверх, +Z вперёд. Для Motors и Propellers подготовьте одну деталь вокруг её начала координат: визуальный код размещает её на четырёх точках крепления. Frame, Battery и Camera используют одно крепление.

Материалы можно хранить внутри GLB или переопределять по имени меша:

```json
"materials": [
  {
    "mesh": "motor-shell",
    "baseColor": "#bfc4cc",
    "baseTexture": "paint.png"
  }
]
```

Имя `motor-shell` должно совпадать с именем меша в модели. Пути к дополнительным текстурам задаются относительно пакета; при публикации они превращаются в URL с хешами. Геометрия не определяет массу или тягу: эти параметры задаёт JSON.

## Цена и доступность

| `cost` | Доступность |
|---|---|
| `0` | Деталь сразу доступна зарегистрированным пилотам. |
| Положительное число | Карточка видна, но перед сохранением её нужно купить за кредиты. |

Допустимая цена — от 0 до 10 000. Чтобы продавать деталь из примера за 150 кредитов, измените `"cost": 0` на `"cost": 150`. Купленная деталь доступна этому аккаунту в разных модифицированных сборках. Гостям сервер предоставляет все детали без покупки.

## Поддерживаемые категории

| Значение `category` | Название в Workbench | Основные параметры |
|---|---|---|
| `frame` | Frame | `mass`, `durability` |
| `motors` | Motors | `mass`, `thrust`, `response` |
| `propellers` | Propellers | `mass`, `thrust`, `drag` |
| `battery` | Battery | `mass`, `duration` |
| `camera` | Camera | `fov` — поле зрения, 75–125° |

`mass` — прибавка к массе базового дрона; `thrust`, `response`, `drag`, `duration` и `durability` — множители. Для новой детали удобно скопировать существующий пакет той же категории и изменить нужные значения. Например, камера должна иметь осмысленный `fov`, а двигатель — `thrust` и `response`.

### Новая деталь и новая категория

Новый двигатель, аккумулятор или камера добавляются JSON-пакетом в уже поддерживаемую категорию.

Совершенно новая категория, например `antenna`, требует реализации в коде. Сейчас проверка каталога отклоняет неизвестные категории. Для расширения нужно:

1. Зарегистрировать категорию в `shared/catalog.js` и `shared/catalog-schema.js`.
2. Добавить её штатное значение в `defaultBuild()` и определить физическое поведение в `shared/physics.js`.
3. Добавить название категории и описание параметров карточки в Workbench (`src/main.js`).
4. Определить крепление модели при необходимости (`public/content/recipes.js`) и обновить инструменты авторинга, если категория должна редактироваться там.
5. Проверить сохранение существующих сборок и серверную проверку доступности деталей.

## Добавление целого дрона

Для нового оригинального дрона используйте `content/drones/<id>/drone.json`, при необходимости с `model.glb` рядом. Возьмите существующий `content/drones/swift/drone.json` за основу и задайте собственные ID, название, размеры, массу, параметры полёта и коллизию. Значение `"unlock": "starter"` делает его доступным сразу. После публикации он появляется среди Original в Drone Selection; для изменения деталей создаётся его Modified-копия.
