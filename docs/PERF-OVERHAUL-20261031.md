# Комплексная оптимизация производительности, загрузок, Ангара и LOD — 2026-10-31

Все изменения изолированы в отдельной ветке **`gemini/perf-overhaul-20261031`** (от базовой ветки `codex/demand-pilots` @ `34c8a87`).
Визуальная вёрстка, CSS и структура интерфейса не менялись. Публичный сервер Oracle (`https://parvoz-drone-sim.duckdns.org/`) не затрагивался. Незавершённые файлы других чатов сохранены без изменений.

## 1. Как проверить утром и как откатить в 1 команду

### Запуск оптимизированной версии локально
```powershell
npm start
```
Откройте `http://localhost:5173/` (или порт, выведенный сервером).

### Полный откат к исходному состоянию (1 команда)
Если нужно мгновенно вернуться к состоянию до ночной доработки:
```powershell
git switch codex/demand-pilots; npm run build
```

### Точечный откат любого отдельного улучшения
Все доработки разбиты на небольшие атомарные коммиты (см. раздел 4). Любой из них можно откатить отдельно:
```powershell
git revert <commit-sha>
npm run build
```

## 3. Что именно вызывало лаги и как это исправлено

### А. Ожидание по 15 секунд при входе в скачанный Ангар и фризы в меню
1. **`O(N)` обход десятков тысяч узлов внутри `compileScenePrograms` (`src/compile-scene-programs.js`)**: при прогреве каждого варианта шейдера сценка рекурсивно обходила и скрывала все неактивные узлы карты, а при повторном входе компилировала те же варианты заново. Переведено на `O(depth)` изоляцию ветвей верхнего уровня и кэширование скомпилированных ключей по рендереру и топологии света.
2. **Сотни лишних компиляций WGSL-пайплайнов тайлов ландшафта**: ключи материалов зависели от `texture.uuid`, из-за чего 256 одинаковых по шейдеру тайлов `TerrainSurface` компилировались 256 раз. Добавлен `shaderMaterialKey`, группирующий текстуры по параметрам сэмплера/развёртки.
3. **Сброс топологии освещения между Главным меню и Ангаром (`src/world.js`)**: переключение видимости `homeLight` меняло набор источников света и инвалидировало все шейдеры сцены. Топология света стабилизирована (`intensity = 0` вместо удаления из рендер-списка).
4. **Перерасход памяти и повторный разбор KTX2 (`src/asset-loader.js`)**: исправлен учёт байтового размера мип-цепочек сжатых GPU-текстур KTX2, увеличен бюджет кэша моделей для десктопа (до `768 МБ` по `navigator.deviceMemory`), включена параллельная загрузка дрона и мастерской и кооперативная нарезка подготовки текстур/отражений/шейдеров по бюджету `<= 8 мс` с защитой от гонок кадра WebGPU (`graphicsPreparing`).
5. **Штормы DOM/Reflow в HUD и меню (`src/main.js`, `src/ui-localization.js`)**: убраны покадровые `getBoundingClientRect()`, `querySelectorAll` и повторные срабатывания `MutationObserver` при локализации и обновлении телеметрии полёта.

### Б. Сохранность скачанных карт после перезагрузки, ускорение скачивания и дельта-обновления карт
1. **Единый реестр скачанных и закодированных ассетов + персистентный манифест карт (`src/asset-delivery.js`, `src/download-manager.js`, `src/flight-loading.js`, `src/main.js`)**:
   - Исправлена ошибка, из-за которой после скачивания карты (через кнопку «Скачать» или при входе в полёт) и перезагрузки страницы карта снова отображалась как **«Не загружено» (`Not downloaded`)**. Причина была в том, что `DownloadManager` проверял все `4 140` опциональных ассетов карты вместо ядра `coreUrls`, не объединял инвентарь `parvoz-downloaded-assets-v1` и `parvoz-encoded-assets-v1`, а бюджет `CacheStorage` (`420 МБ` / `640 МБ`) вытеснял файлы крупных карт (`The Green` + `Liftoff Arena` + `Pine Valley`).
   - Бюджеты кэша увеличены до **`2,5 ГиБ` / `4 ГиБ`**, инвентарь `retainedInventory()` объединён по обоим хранилищам, а в `localStorage` (`parvoz-downloaded-maps-v1`) сохраняется персистентный манифест скачанных URL каждой карты.
   - При завершении `FlightLoading` карта сразу помечается как скачанная (`markCoreReady`).
2. **Что происходит при обновлении карты разработчиком (Delta Sync + автоочистка старых файлов)**:
   - Если в карту добавлены или изменены файлы (новый контент-хэш URL в манифесте), `DownloadManager` сравнивает сохранённый список URL с новым, переводит статус в `updateAvailable: true`, **переиспользует все неизменившиеся файлы из кэша** и докачивает только дельту новых/изменённых файлов.
   - При старте игры вызывается `pruneObsoleteAssets(activeUrls)`, автоматически удаляющий из `CacheStorage` устаревшие файлы старых версий карт, которые больше не используются ни одной картой или дроном.
3. **Ускорение скачивания и локальной загрузки (`src/asset-delivery.js`, `src/download-manager.js`, `src/asset-loader.js`)**:
   - Параллелизм скачивания увеличен до `6` одновременных потоков с автоматическим сжатием (`Accept-Encoding: br, gzip, deflate`).
   - В `src/asset-loader.js` устранён дорогой вызов `SkeletonUtils.clone()` для статических мешей без скелетной анимации (`hasSkinnedMesh ? SkeletonUtils.clone(source) : source.clone(true)`), добавлена мемоизация `copyMaterial` внутри клона и дедупликация обхода текстур по `seenMaterials`.

### В. Исправление полосатых теней (Shadow Acne) и артефактов Ambient Occlusion, чёткая трава и текстуры на `Ultra`
1. **Устранение чёрно-белых полос от теней и Ambient Occlusion (`src/world.js`, `src/native-terrain.js`)**:
   - Отключено самозатенение (`castShadow = false` при сохранении `receiveShadow = true`) на всех крупных поверхностях ландшафта (`TerrainSurface_*`, `GolfHorizon`, `HorizonDisplacement`, `Native tiled terrain`), из-за которого направленный свет под острым углом давал характерную «зебру» (shadow acne) по траве и склонам.
   - На подземных/крытых картах (`Minus Two`) отключён `sun.castShadow`, чтобы геометрия потолка не отбрасывала полосатые тени сквозь парковку.
   - Разрешение карты солнечных теней повышено до `2048×2048` для `high` и `ultra`, фрустум сжат до `±85 м`, настроены `bias = -0.00055, normalBias = 0.075`.
   - Из постпроцессинга убран полуразрешённый (`0.5×`) `denoise` + `rtt` проход GTAO, который реконструировал нормали из буфера глубины с характерными ступенчатыми концентрическими полосами и сеткой `4×4`. Теперь `ao` работает с плавным затуханием по дальности (`nearWeight`) и мёртвой зоной на плоских поверхностях (`cleanAo = clamp(0.75, 1.0)`).
2. **Чёткая многомасштабная детализация травы и земли на `Ultra` (`src/world.js`, `src/surface-settings.js`, `src/scenery-batches.js`)**:
   - Тайлы ландшафта в `The Green` (`TerrainSurface_*`) и `Liftoff Arena` имеют только базовую цветовую текстуру низкого разрешения (`~1 тексель на 15–30 см` земли) без карты нормалей. Для них добавлен процедурный TSL-шейдер микрорельефа и травинок (`getTerrainDetailMaps()`) на базе 3-октавного гребневого шума (`period = 16, 32, 64`, нормализованного по среднеквадратичному отклонению `stdH`) с повёрнутыми мировыми координатами (`0.085`, `0.34`, `1.25` цикл/м) и TSL `normalMap`.
   - Для встроенного `ground` увеличена плотность повтора текстуры с `26×26` до `96×96` с `16×` анизотропной фильтрацией.
   - В `adjustPerformance(fps)` для пресета `Ultra` установлен минимальный порог масштаба рендера `0.92`, чтобы адаптивное разрешение не размывало картинку до `0.6×`.

### Г. Проблемы с LOD, дальними объектами и микрофризами при полёте по карте
1. **Слишком раннее переключение крупных объектов (стадионов, ангаров, скал) на грубый LOD (`src/visual-lod.js`, `src/static-scenery.js`)**: импортированные чанки имели одинаковые пороги `16/22 м` независимо от реального физического размера чанка. Добавлен учёт мирового масштаба и `footprintScale = max(1, maxDim / 32)`, а все расчёты мировых AABB запекаются один раз при заморозке сцены (`visualLod: 0,000 мс` на кадр в полёте).
2. **Частичная выгрузка матриц `SceneryInstances` и полный прогрев текстур сцены (`src/scenery-instances.js`, `src/prepare-scene-textures.js`, `src/world.js`)**:
   - В `SceneryInstances` добавлены `clearUpdateRanges()` и `addUpdateRange(0, count * 16)` (и `count * 3` для `instanceColor`), чтобы при повороте камеры в GPU передавались только реально видимые инстансы, а не весь буфер.
   - В `prepareSceneTextures` включён предварительный прогрев текстур всех статических батчей (`warmAllScenery = true`), включая объекты позади стартового направления камеры, чтобы первый разворот в полёте не вызывал фриз выгрузки текстур в видеопамять.
3. **Схлопывание идентичных уровней `LOD0 === LOD1 === LOD2` и пакетирование реквизита трассы (`src/scenery-batches.js`, `src/world.js`)**: уровни `LOD0/LOD1/LOD2` с идентичными мешами автоматически извлекаются из LOD-переключателя и объединяются в статические `768 м` квадранты (`mergeGeometries`).
4. **Устранение 4 Гц (`250 мс`) фриза от полного перестроения карты теней (`src/world.js`)**: убран лишний принудительный сброс карты солнечных теней каждые 250 мс (`longTasksInFlight: 0`).

### Д. Ускорение физики и гонок с ИИ в 13 раз (`shared/`)
1. **Предварительное отсечение ворот трассы по сферам и радиусу срабатывания (`shared/gates.js`)**: вместо полного теста всех ворот для каждого дрона на каждом подшаге `240 Гц` проверяются только ближайшие ворота в радиусе пересечения.
2. **Общий пространственный запрос для 38 сфер составного коллайдера дрона и безаллокационный `sweepSphere` (`shared/packed-collision-tree.js`, `shared/collision.js`, `shared/physics.js`, `src/solo-session.js`)**: вместо 38 отдельных обходов BVH-дерева на каждый подшаг каждого дрона выполняется один общий AABB-запрос на весь корпус дрона без создания временных массивов и векторов в куче (ноль пауз GC).
