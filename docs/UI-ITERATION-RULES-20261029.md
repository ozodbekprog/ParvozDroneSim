# UI: продолжение от текущей публичной версии

29 октября 2026, Asia/Tashkent. Основание — прямое указание пользователя в
этом чате. Это рабочее правило, а не одобрение нового внешнего вида.

## Решение пользователя

Показанные новые изменения UI не понравились. Их нельзя применять в публичной
игре; существующий публичный интерфейс должен остаться как есть.

Дальнейшая работа начинается с **полного текущего публичного UI**, включая его
структуру, логику, компоновку и состояния. Прежний подход с созданием новых
панелей поверх одного фонового кадра не является подходящей исходной точкой.
Локальный checkout уже содержит отдельные неопубликованные UI-правки: их нельзя
по умолчанию считать интерфейсом, который сейчас видят игроки.

Доработка идёт небольшими итерациями. Внешний вид в итоге может измениться
значительно, если к этому приводит последовательность просмотренных шагов.
Правило не ограничивает задачу одними отступами или исправлением имён.

## Разрешение на публикацию

1. Новые варианты проверяются отдельно — в тестовой версии или превью.
2. Пользователь проверяет результат и решает, какие изменения выпускать.
3. Публичный UI меняется только после явного разрешения на выпуск показанного
   результата. Просмотр или одобрение локального варианта сами по себе не
   являются разрешением на публикацию.
4. Прежние общие просьбы продолжать разработку/публиковать игру, установки
   инструментов и разрешение на Git commit/push не заменяют этот допуск.
5. При выпуске не связанных с UI исправлений нельзя попутно включать
   неразрешённые UI-правки из текущего checkout.

Это уточняет прежние инструкции о доведении согласованных задач до Oracle:
сейчас выпуск новых UI-изменений не разрешён. GitHub остаётся отдельной
историей проекта; сохранение документации или превью не обновляет игру.

от публичного UI; их наличие не является целью или гарантией качества.

## Порядок следующей итерации

1. Снять/проверить текущий публичный экран целиком и его нужные состояния.
   Зафиксировать версию клиента, язык, размеры окна, выбранный дрон/сборку и
   маршрут в UI. Снимок 28 октября — исторический ориентир до свежей проверки.
2. В отдельной тестовой копии сначала воспроизвести исходный UI без изменений.
   Использовать соответствующие опубликованной версии исходники/стили;
   локальную более новую сборку не выдавать за точное исходное состояние.
3. Назвать одну конкретную проблему структуры, логики или компоновки, объяснить
   её влияние и предложить небольшой шаг. Не менять заодно палитру, форму всех
   панелей и несколько несвязанных экранов. Согласование стиля и плана остаётся
   обязательным в объёме, ранее заданном пользователем.
4. Показать исходное и изменённое состояния рядом или с переключением в одинаковых
   условиях. Указать точную разницу, проверить затронутую функцию, сохранить
   реальные изображения дронов и не перегружать игрока информацией.
5. Получить отзыв, скорректировать шаг и только затем переходить к следующему.
   Публиковать лишь явно разрешённый результат по обычным правилам Oracle.

В этом ходе закреплены правила и статус материалов; новый UI, код игры и
развёртывание не выполнялись.
