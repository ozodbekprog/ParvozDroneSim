## Routine changes

Check the checkout before editing:

```powershell
git status --short
git branch --show-current
git remote -v
git fetch origin
# Only with a clean working tree, on the intended tracking branch:
git pull --ff-only
```

Run the checks affected by the change. Stage explicit files, inspect the diff
and create a descriptive commit; do not sweep another chat's unfinished work
into your commit. A GitHub push does not update the live game on Oracle.

```powershell
git add -- path/to/changed-file
git diff --cached --stat
git diff --cached
git commit -m "Describe the finished change"
git push
git rev-parse HEAD
git ls-remote origin refs/heads/BRANCH
```

The two SHA values must match before reporting the push as completed. If a
concurrent push prevents updating the branch, fetch and resolve the divergence
without discarding anyone's changes. Never force push or use destructive reset
commands to make a backup succeed. Report an unfinished push explicitly.

## Continue on another computer

Install Git, Git LFS and Node.js 24 or newer. Authenticate with the GitHub
account that has access to this private repository, then clone the `origin`
URL shown by `git remote -v`:

```powershell
git lfs install
git clone REPOSITORY_URL DroneLiftoffUz
cd DroneLiftoffUz
git lfs pull
npm ci
npm run content:sync
npm run content:check
npm run build
npm start
```

The tracked `content/` contains all three active maps, 17 routes, six drones,
workshop deliveries, editable Blender files and provenance. Git tracks the
contents of the existing Windows junctions as regular files, so a new checkout
does not require drive D: to run, build or edit the saved sources. The retained
`public/content/catalog.json` supplies the existing bootstrap/defaults; hashed
deliveries and inspection caches are regenerated by `content:sync`.

Full Liftoff re-extraction is a separate operation: it still requires the
installed game and the preserved import caches under
`D:/DroneLiftoffUz-import-temp/preserved-cache`. Those caches are excluded from
Git, must not be deleted, and are unnecessary for ordinary code work. Do not
repeat recovery just to start on another computer.

Player accounts/progress, secret env files, SSH credentials and local SQLite
databases are deliberately excluded. A new local server creates its own local
database; it does not restore or replace the production database. Transfer
necessary secrets separately when setting up deployment access.

## Undo a completed change

Use `git log --oneline` to find the unwanted commit. On a clean checkout:

```powershell
git revert COMMIT_SHA
# Run the affected checks, then:
git push
```

This adds a visible reversal and preserves the shared history. To inspect an
older version without changing the current branch, use a separate checkout or
`git switch --detach COMMIT_SHA` only after saving current work. A previous game
version also needs a separate verified Oracle release if players should receive
it; database rollback is not part of a code revert.

## Assets, privacy and storage

Keep the repository private while it contains imported Liftoff assets. Preserve
authors, source links and permission metadata. The online multiplayer test
authorization does not establish a redistribution license.

`.gitattributes` stores models, editable `.blend`, images and the verified
Ironworks ZIP through Git LFS. Never force-add ignored source autosaves,
intermediate `*.prepared.glb`, cached deliveries, tools, temporary test folders,
database backups or release stages. Keep the current and previous Oracle
release archives locally for operational rollback; they are separate from Git.

GitHub Free currently includes 10 GiB of LFS storage and 10 GiB of download
bandwidth per month. Each changed binary version consumes additional storage;
downloads consume the owner's bandwidth. See the official
[Git LFS billing documentation](https://docs.github.com/en/billing/concepts/product-billing/git-lfs).
Do not enable paid storage or change billing settings. `.git/lfs` keeps a local
asset cache, so the working folder includes both working assets and Git storage.

Ironworks remains retired. Its only full local backup is
`backups/ironworks-v2-20261013.zip` (also tracked through LFS), with a SHA-256
sidecar. Restore it manually only on an explicit request; older generated maps
remain in `content/archived-maps/`.
