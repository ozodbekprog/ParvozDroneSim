# Локальная приёмка Parvoz

Первый воспроизводимый процесс приёмки, управляемый агентом в текущем Codex.
Раннер выполняет машинные проверки, сохраняет этапы и ожидает браузерные
доказательства от штатного Chrome-инструмента. Модельные запросы, смена входов,
сообщения в другие чаты, развёртывание и расписание в него не встроены.

## Запуск

Из папки проекта, в PowerShell:

```powershell
npm run acceptance -- start --recovery-dir 'C:\Users\User\Documents\ChatGPT\Nvidia-spark\tools\chatgpt-recovery' --thread 01a16814-7ec9-7350-8c63-80b109c630ac --serve
```

Путь указывает на существующий монитор из чата «Автоматизировать смену
аккаунтов». На другом компьютере передать местный путь через `--recovery-dir`
или `CHATGPT_RECOVERY_DIR`. Требуются установленный Node 24+, Python и уже
настроенный Codex CLI. Раннер вызывает существующий `quota_probe.py`, который
читает лимиты через штатный app-server. Не копирует и не меняет авторизацию.
При отсутствии свежих показаний останавливается со статусом `quota_unknown`.
При отдельном CODEX_HOME проверить, что CLI наблюдает нужный вход приложения.

Порог берётся из `%LOCALAPPDATA%\ChatGPT-Recovery\settings.json`, если он
корректен; иначе 5%. `--threshold 3` задаёт его для одного запуска.

Результаты — `data/acceptance/<run-id>/`. `data/acceptance/latest.json` содержит
последний ID. Прочитать `checkpoint.json`, `REPORT.md` и `CONTINUE.md`.

```powershell
npm run acceptance -- status --run <run-id>
npm run acceptance -- resume --run <run-id> --serve
npm run acceptance -- reconnect --run <run-id>
npm run acceptance -- accept --run <run-id> --evidence 'data/acceptance/<run-id>/browser-proof.json'
```

`--serve` оставляет тестовый сервер на `127.0.0.1:2589` до подачи доказательств,
остановки или 15 минут. Другой порт — `--port 2590`. Занятый порт не используется
повторно и чужой сервер не останавливается. Раннер без `--serve` завершает сервер
после машинных проверок; `resume --serve` поднимает его снова.

## Что автоматизировано

1. Копирование исходников, тестов и метаданных контента в отдельную рабочую
   папку. Проверка SHA-256 до/после копирования обнаруживает параллельные правки.
2. 37 выбранных проверок диагностики, кадров, меню, контроллера и самой приёмки.
   Состав может меняться вместе с тестами; истинный счётчик — в журнале.
3. Валидация существующего контента и отдельная сборка Vite. `prebuild` и
   повторный импорт больших ресурсов не запускаются.
4. Отдельный loopback-сервер с собственной SQLite-базой. Два тестовых гостя,
   комната, готовность ассетов, управление и снимки симуляции проверяются
   существующим `smoke-lan.js` на этом экземпляре.
5. Сохранение результата каждого этапа, журналов и следующего действия.
   Прерванный этап повторяется; завершённые этапы того же снимка пропускаются.
6. Чтение обоих окон лимита перед этапами и каждые 30 секунд ожидания браузера.
   Остаток на пороге сохраняет checkpoint и останавливает этот раннер. Это не
   нажатие Stop в Codex и не гарантия спасения любого активного модельного хода.
7. Новый наблюдаемый аккаунт сбрасывает браузерное подтверждение. Возобновление
   проверяет исходники; при изменениях нужен новый снимок вместо подмены отчёта.

Установленные node_modules и большие уже скомпилированные публичные ресурсы
используются через junction; каталог контента и исходники копируются. Это
изоляция кода, сборки и базы, а не копия всех гигабайтов ассетов или контейнер.
Раннер пишет только внутрь своего каталога. Параллельную переустановку зависимостей
или перегенерацию ассетов во время приёмки следует завершить до запуска.

## Chrome и смена аккаунта

Прочитать [BROWSER-SCENARIO.md](BROWSER-SCENARIO.md). Работать через `cua_repl`.
Раннер сам не кликает по игре: браузерный этап выполняет текущий агент через
разрешённый инструмент и прикладывает его реальные снимки/наблюдения.
`browser-proof.json` — запись наблюдений агента, а не криптографическое
подтверждение происхождения снимков. Раннер проверяет полноту, время, аккаунт,
снимок исходников, адрес тестового сервера и существование файлов доказательств.

При недоступном Chrome сначала проверить, открыт ли он. После мягкого
восстановления найти то же расширение/профиль заново: идентификатор соединения
может измениться. Старая ссылка на вкладку тогда перестаёт работать, хотя
вкладка остаётся открытой. Повторно привязать её через новый идентификатор и
проверить чтение/действие в этом чате.

`reconnect` вызывает только существующий `Recovery.ps1 -Action Reconnect`,
который перезапускает зарегистрированный native host. Он сбрасывает browser proof,
но не помечает доступ к Chrome восстановленным. Если Chrome закрыт, сначала
запустить его штатным инструментом. Если выдаётся запрет доступа после смены
аккаунта, сохранить checkpoint, проверить штатные настройки вручную и при
необходимости воспользоваться существующим ярлыком полного перезапуска после
сохранения работы. Из активного раннера приложение не перезапускается.

Смена аккаунта выполняется обычным доступным пользователю способом. Затем
пользователь возвращается в тот же чат и пишет `continue`, либо агент продолжает
разрешённый ход. `CONTINUE.md` указывает ровно тот запуск, который надо поднять.
Автоматического управления самим окном Codex или подмены разрешений здесь нет.

## Статусы и ограничения

- `passed`: выбранный пилот принят на зафиксированном снимке.
- `failed`: конкретная проверка не прошла, причина в журнале. Исполнитель
  исправляет источник и создаёт новый снимок. Бессмысленных бесконечных повторов нет.
- `awaiting_browser`: машинные проверки готовы, Chrome ещё не подтверждён.
- `waiting_for_quota` / `quota_unknown`: сохранено; требуется свежий доступный лимит.
- `source_changed`: исходники проекта отличаются от снимка.

Для start/resume коды завершения: 0 — пройдено, 2 — провал, 3 — незавершено,
4 — ожидание квоты, 1 — ошибка операции. `accept` сообщает статус в JSON.
`status` только читает сохранённые данные. Снимки приватны и остаются в ignored
data; в Git хранится инструмент и краткий отчёт.

Это пилот меню диагностики/справочника и сетевого smoke, не приёмка всего
продукта. Он не подтверждает FPS UHD 620, не чинит стуттер без измерений,
не обновляет Oracle и не запускает других агентов между сообщениями.
Для новых типов изменений нужны подходящие критерии/сценарии и тесты.

## Проверка остановки

`--quota-file <path>` заменяет чтение квоты для контролируемого теста.
Использовать синтетические значения только в тестовых запусках; не выдавать их
за реальный остаток. Возобновление без этого флага возвращает живое чтение.

Первый реальный прогон: `docs/ACCEPTANCE-PILOT-20261027.md`.
